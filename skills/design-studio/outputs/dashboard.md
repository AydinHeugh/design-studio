# Output: dashboard

**Packs:** taste, emil (light), dataviz, copy, assets.

## Rules
- **Data must be real** or clearly marked as sample data. Never invent numbers.
- **Show what to do, not just what happened.** Put the key insight next to the chart (from Mobbin's study of 2,108 dashboards).
- **Pick the visual that fits the data:** a map when location matters, a heat map for busy times; not a default bar chart for everything.
- **Don't repeat the same KPI row** across screens.
- **Clean beats busy.** Most dashboards are busy; the memorable ones knew what to leave out.
- **Motion** only to show change: a value updating, a chart drawing in.
- **Empty states** can be useful or even rewarding, never just a blank table.
- Consider a **metric of the product's own** only if the user wants one.

## Stack (new projects)
Next.js + Recharts (or the user's chart library) + shadcn/ui.
