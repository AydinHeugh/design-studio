# Interview

**First, check the content is settled.** "Do you know what this needs to say and show (sections, real text, real images or data)?" If not, help settle it first, or agree that directions are clearly labeled demos.

Then ask, clickable where possible, always leaving room for their own answer:
1. **The one real thing:** what can this show that no competitor could? (A live product, a real photo, their own data, a tool people can use right away.)
2. **Readers:** see `readers.md`.
3. **References:** things they love and one they hate, and *what specifically*. "I like Stripe" isn't a reference; "Stripe's code sample is the hero" is.
4. **Constraints:** brand assets, platform, stack, existing design system.
5. **Real use:** where and how is it actually used? Desk, phone mid-task, printed, projector, glanced at for two seconds? This sets type size, density and contrast.
6. **Your idea first:** "Do you already have a layout, sketch, screenshot or reference in mind?" If yes, direction 1 is built from it.

Light depth: ask at most one question (usually 6), and state your assumptions for the rest so the user can correct them.

Ask follow-ups only when an answer is vague. Translate vague words (`coach.md`) and confirm.
